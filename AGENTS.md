# AGENTS.md — «شاهد من القرآن» (quran-tag)

Vanilla static Quran PWA (no build step, no frameworks, no npm/CI/tests). Arabic-first RTL UI. Serve over HTTP when testing (e.g. `python3 -m http.server`) — service worker + `fetch()` of `data/*.json` break on `file://`.

## Repo map
- `index.html`, `app.js`, `styles.css` — main app (plain ES5 `var`-style JS; `app.js` is a single ~4800-line IIFE).
- `lab.js` — tag-lab graph canvas, lazy-loaded only on `#/lab` via `window.QuranLabBridge`.
- `lib/` — vendored `pdf.min.js` / `pdf.worker.min.js` / `fflate.min.js` for PDF/DOCX citation import; loaded on demand only.
- `fonts/` — KFGQPC Uthmanic Qaloun v2.1 + Hafs v18 (+ rakkas display). Do NOT swap the qaloon font for an older KFGQPC build: its U+0649 (alef maqsura) glyph was empty, so ى rendered blank.
- `rewrite_spec.py` — DSPy prompt-rewriter whose embedded `QURAN_TAG_SPEC` is the most complete architecture spec in the repo; read it before non-trivial features.
- `loader-star.html` — legacy loading snippet, kept for reference only.
- `skills/` — auto-generated editor session files, **do not commit** (`.gitignore` only has `.DS_Store`, so it stays untracked manually).
- `USER_GUIDE.md` — user-facing Arabic guide.

## Data rules (non-negotiable)
- `data/quran.json` (Qaloon, 6214 ayahs) and `data/hafs.json` (Hafs, 6236) are reference text: **NEVER modify, not even cosmetically** — all display normalization happens in the rendering layer.
- `quran.json` ayah arrays **exclude the basmala** (surah 2 = 285, 9 = 130); `hafs.json` is with-basmala (surah 2 = 286, 9 = 129). `state.quran` points at the ACTIVE riwaya dataset (`applyRiwaya()` swaps it + resets `normVersesCache` + sets `html[data-riwaya]` which flips the mushaf font); text is indexed `verses[ayahNumber-1]`.
- `data/numbering.json` — canonical Qaloon→Hafs ayah-range maps for the 59 surahs where the two counts don't align 1:1 (the other 55 are identity). Generated by tooling in the temp opencode dir (`gen_numbering.py` etc.); never hand-edit.
- Seed tag-books (`data/dawaa|jam3|asarar|adib|dirasat.json`) merge into tags lazily on first `#/tags` visit (`ensureSeeds()`); deliberately NOT precached.
- `data/quran-new.json` is unreferenced by app code (legacy copy).

## Canonical cross-riwaya numbering (tag keys)
Tag verse keys `"surah:ayah"` and memorize session ranges are stored in **Hafs (canonical) numbering**, not the active riwaya's:
- `canonVerseKey(surah, ayah)` / `canonAyah()` — active-riwaya ayah → canonical hafs ayah (identity when hafs active).
- `activeAyahOf(surah, h)` — inverse, for rendering stored keys in the active riwaya.
- `storedIdsForActive()` — in qaloon mode also collects every hafs key inside the verse's mapped range (one qaloon verse can cover 2 hafs ayahs).
- `saveTags()` stamps `num:'hafs'`; memorize saves `{num:'hafs', from, to}` via `canonAyah`. `migrateLegacyNumbering()` is a one-time boot migration of pre-canonical qaloon keys (keys beyond the qaloon verse count are treated as already-hafs). Hafs dataset fetch failure reverts riwaya to qaloon.
- **Audio numbering is different**: 1:1 with the ACTIVE dataset's rendered ayah numbers (see below) — never mix with canonical keys.

## Tag-suggestion engine (ontology)
Lives in `app.js` (after the `lab.js` bridge). Flow:
1. `loadOntology()` fetches `data/ontology.json` once (`ontologyStatus` idle→loading→ready). 569 concepts `{ w, d[] }` mapping lexicon words to thematic domains (c1..c24) from «التفسير الموضوعي لسور القرآن الكريم».
2. `suggestTagsForCategory(catId, max)`:
   - text = category name + its tag names; grounding = `categoryBoundAyahsText(catId)` (all ayahs carrying a tag of that category).
   - scores each concept via `matchConceptToCategory`, **excludes any root already used as a tag** (`existingRoots`).
   - if nothing scores → falls back to a fixed generic list (الإيمان، العبادة، …) at 0.35.
   - returns `{word, score, rel, domain}` descending; accept creates a tag via `createTag(word, TAG_COLORS[i%…], scid, '', 'suggest:'+scid)`.

### Matching invariants (do not regress)
- **Token-boundary only.** `matchConceptToCategory` never uses `indexOf` substring matching (the old matcher's `indexOf(root)` hit inside unrelated words like إسماعيل/الطغيان for a التوحيد category). It builds whole-word sets (`tok:T`, `root:R`) via `tokenSet(text)` and measures `conceptCover(cTokens, sets)` = fraction of the concept's tokens found as full words in the category name (×0.55) and bound ayahs (×0.85).
- **`arabicRoot` is conservative**: keeps `الله`/`اللهم` intact; strips ONLY the definite-article joins (`وال|بال|فال|لل|ال`) and a leading wasla alef. NEVER strips single-letter `و/ب/ك/ف/ل` (they're real root letters: الكفر، الوحي، البر). Returns the full article-stripped stem, no 3-char truncation.
- **`normalizeWordForMatch`**: wasla alef ٱ→ا first, then removes ALL diacritics + Qur'anic annotation signs (`\u0610-\u061A`, `\u064B-\u065F`, `\u0670`, `\u06D6-\u06ED`, `\u0640`, `\u08F0-\u08FF`) so `بِٱللَّهِ`→`بالله`, `اِ۬لدِّينِ`→`الدين` stay one token. Keep-range includes `\u06D0-\u06D3`.

## Service worker
Bump `const CACHE = 'quran-tag-vNN'` in `sw.js` for ANY change to precached assets (app.js, lab.js, styles.css, index.html, fonts, icons, manifest, `surahs/quran/numbering.json`) — stale caches have caused phantom errors before. `hafs.json` + seed books are fetched lazily (runtime cache-first, offline once fetched).

## Audio / riwaya
RIWAYA = `{ qaloon, hafs }`; `currentRiwaya()` reads LS `qaloon_riwaya`. Shared builder `riwayaAudioUrl(surah, ayah)` resolves by `currentRiwaya()`; `memAudioUrl` and `rdrAudioUrl` both delegate to it.
- Qaloon → quranpedia recitation 257 (`https://files.quranpedia.net/recitations/257/{surah%03d}{ayah%03d}.mp3`; verified `200 audio/mpeg`, `access-control-allow-origin: *`, Range support).
- Hafs → `https://everyayah.com/data/Husary_128kbps/{surah%03d}{ayah%03d}.mp3`.
- **Audio numbering == active dataset's rendered ayah numbers** (qaloon files match no-basmala counts: surah 2 = 285, 4 = 175, 9 = 130, 40 = 84; hafs files match with-basmala counts). Never re-derive offsets.
- Repeat selects exist on BOTH reader and memorize (`rdrAyahRep`/`rdrSurahRep` and `memAyahRep`/`memSurahRep`, all rendered via `memRepOptions`/`memRepDefault`). LS keys `qaloon_mem_ayahrep`/`qaloon_mem_surahrep` — valid values `1`, `inf`, or any prime in 2..47 (`MEM_REP_PRIMES`); prefs are read from the DOM selects at start, not LS.
- Loop state machines: `memAyahEnded` (ayah-repeat → advance → session wrap via `memAudio.pass`) and its `rdr*` mirror in `app.js`.
- Lifecycle: `rdrStopAudio()` on route change / riwaya toggle / reader re-render (highlight `.verse.rdr-playing`); `memStopAudio()` at the top of `renderMemorize()` and in `render()` when leaving `#/memorize` (highlight `.verse.mem-playing`).
- Host is Cloudflare rate-limited: rapid curl probes return `000` and trigger a short-lived IP ban; probe with several-second spacing and a browser UA.

## Plans module (خطة قراءة/استماع/مراجعة/حفظ) — lazy-loaded
`plans.js` (IIFE over `window.QuranPlansBridge`, same pattern as `lab.js`); route `#/plans` triggers `lazyLoadPlans()` in `app.js`. Up to 8 plans in LS `qaloon_plans_v1`.
- **Partitioning is canonical**: chunks are built in Hafs numbering via `plansBuildChunks` (`plansHafsCount` derives a surah's hafs ayah count from `numbering.json`'s max range end — no hafs.json fetch needed); rendering converts via `activeAyahOf`. Verified by `plans_diag.js` harness in the temp opencode dir (extracts functions from `plans.js`; whole-mushaf 5-ayahs/day partition = 1248 chunks covering 6236 hafs ayahs exactly once).
- **Types**: read/listen/revise/memorize. Deep-links: memorize → `#/memorize` (`plansPrefillMemorize` writes `LS.memSession` canonical `{surah, num:'hafs', from, to}` on click, before navigation); listen/read/revise → `#/surah/N/M` in active-riwaya ayahs, listening sets sessionStorage flag `qaloon_plan_listen` consumed by `plansMaybeAutoplayReader` (app.js wrapper at the end of `renderReader`) to autostart `rdrStartAudio`.
- **Spaced repetition** (`PLAN_REVIEW_STEPS = [1,3,7,14,30]` days): checking a revise/memorize chunk stamps `done` + `nextReview`; due reviews render per-plan («مراجعات اليوم», rollover automatic since any `nextReview <= today` shows). Completing the 50-rep loop in memorize (`memState.reps === 0`) fires `plansNotifyMemorizeDone` — an app.js wrapper that **loads plans.js on demand** (`ensurePlansScript`) then auto-checks the current memorize chunk, so it works even if `#/plans` was never visited.
- `plans.js` is SW-precached (like `lab.js`) but executed only on first `#/plans` visit or memorize completion; the header icon + «الخطط» pills live in `index.html` / reader/tags toolbars.
